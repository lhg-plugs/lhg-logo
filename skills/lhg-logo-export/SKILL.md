# lhg-logo-export：导出与应用自检

> 目标：交付的不是"一个 SVG"，而是"一套在各处都能用的资产包"。
> 核心纪律：**导出清单逐项打勾，缺一项都不算交付**。

## 1. 何时使用

- `logo.svg` + `spec.md` 已定稿 → 读本 skill 出导出包
- 用户问"logo 做好了，还需要什么尺寸" → 查第 3 节清单
- 交付前最终自检 → 第 5 节应用场景走查 + 跑审计脚本

## 2. 输入与输出

**输入**：`logo.svg`（规范源文件）、`logo-dark.svg`、`logo-mono*.svg`、`brand.json`。
**输出**：`delivery/` 目录（多尺寸文件 + `brand.json` 终版 + `CHECKLIST.md`）。

## 2.5 交付前 10 分钟检查单

```text
□ logo_audit.py 跑过，blocker=0
□ 16px favicon 肉眼看过（不是"应该没问题"）
□ 深底版是单独调过的（不是反色将就的）
□ 单色版黑白各一份
□ brand.json 里 originality_check 字段不是空的
□ 文件命名符合 logo-<场景>-<尺寸> 规范
□ spec.md 里网格/安全区/最小尺寸三项齐了
```

7 项全勾 → 发 `delivery/` 压缩包；缺一项 → 回去补。**这 10 分钟省下来，售后能花掉你 10 小时。**

## 3. 分步方法论：导出清单

按场景列出**必须**有的尺寸/格式（`brand.json` 的 `exports` 数组即此清单的机器版）：

| 场景 | 尺寸 | 格式 | 备注 |
|---|---|---|---|
| 浏览器 favicon | 16×16、32×32 | PNG（+ SVG 备用） | 16px 地狱模式：糊了就用简化版 |
| 社交媒体头像 | 180×180（微信）、400×400（通用） | PNG | 注意各平台圆形裁切，关键图形居中 |
| APP 图标 | 1024×1024（母版） | PNG | iOS/Android 分别按规范圆角（由开发侧切） |
| 官网/宣传 | 240px、480px 宽 | SVG 优先 | 矢量无限缩放，官网必须用 SVG |
| 印刷 | 矢量母版 | SVG/PDF | 名片/门头/包装：必须给矢量，不给 PNG 放大 |
| 深色场景 | 同上各一 | SVG/PNG | 深底版单独导出，不许拿浅底版"将就" |
| 单色场景 | 1 套 | SVG | 传真/雕刻/烫金：纯黑 + 纯白反白 |

**命名规范**：`logo-<场景>-<尺寸>.<格式>`，如 `logo-favicon-32.png`、`logo-dark.svg`。命名乱 = 资产管理灾难的开始。

## 3.5 导出尺寸速查卡（贴墙上）

```
favicon:      16 / 32            PNG
社交头像:     180 / 400          PNG（圆切注意）
APP 图标:     1024               PNG（母版）
官网:         SVG                矢量优先
印刷:         SVG/PDF            必须矢量
深色场景:     同上各一           深底版单独导出
单色场景:     1 套               纯黑+纯白反白
```

**三句口诀**：屏幕用 PNG（尺寸给足）、网页用 SVG（无限缩放）、印刷必须矢量（放大不糊）。

## 4. 色彩对比度计算（确定性）

logo 在背景上必须看得清——用 WCAG 相对亮度公式算，不靠"看着还行"：

```
L(颜色) = 0.2126×R' + 0.7152×G' + 0.0722×B'  （R'/G'/B' 为线性化后的通道值）
对比度 = (L较亮 + 0.05) / (L较暗 + 0.05)
```

- 正文/标志与背景对比度 **≥ 4.5:1**（`logo_audit.py` 的 COLOR-CONTRAST-001 按 `brand.json` 的 `contrast_pairs` 自动算）
- < 4.5 → warning：要么加深标志色，要么换背景，不要"差不多能看清"
- 深底版单独算一遍（深底对比度陷阱最多）

### 计算实例

主色 `#1A56DB` 在白色 `#FFFFFF` 背景上：

1. `#1A56DB` → R=26, G=86, B=219 → 线性化 → 相对亮度 L ≈ 0.115
2. 白色 L = 1.0
3. 对比度 = (1.0 + 0.05) / (0.115 + 0.05) ≈ **6.36:1** → ✅ 通过（≥4.5）

同一主色在深底 `#111827`（L ≈ 0.009）上：

- 对比度 = (0.115 + 0.05) / (0.009 + 0.05) ≈ **2.80:1** → ❌ 不通过
- 解法：深底版单独提亮主色到 `#7CA3F5`（L ≈ 0.36），对比度 ≈ 6.9:1 → ✅

**结论**：深底版必须单独调色、单独算——这就是为什么 `variants.dark` 是一个独立文件而不是"反色一下"。

## 5. 应用场景走查（交付前人工 + 脚本）

拿着导出包，逐个场景"穿上试试"：

- [ ] **16px favicon**：浏览器标签页上看一眼，认得出吗？
- [ ] **社交头像**：圆形裁切后，关键图形没被切掉吧？
- [ ] **深色模式**：网站切深色后，logo 用的是深底版吗？
- [ ] **单色**：黑白打印/传真一份，还成立吗？
- [ ] **远距离**：门头效果图缩小到 3 米外视角，读得清吗？
- [ ] **竞品并排**：和避让清单里的竞品 logo 放一起，第一眼分得清吗？

走查发现的问题回 `lhg-logo-geometry` 修，不许在导出文件上打补丁。

### 走查问题分级

| 级别 | 示例 | 处理 |
|---|---|---|
| P0（不许交付） | 16px 完全糊掉、深底版没做、对比度 <3 | 回几何规范修，当天改 |
| P1（建议修） | 社交头像圆切切掉一点图形、命名不规范 | 修了再交付，或书面记录已知问题 |
| P2（记录即可） | 某个极小众场景没覆盖（如传真机） | 写进 CHECKLIST.md 备注，不阻塞交付 |

**分级原则**：P0 是"logo 不能用"，P1 是"logo 不好用"，P2 是"极端情况"——不要把 P2 当 P0 修，也不要把 P0 当 P2 放。

## 6. 交付物清单（delivery/）

```
delivery/
├── logo.svg / logo-dark.svg / logo-mono.svg / logo-mono-rev.svg
├── logo-favicon-16.png / logo-favicon-32.png
├── logo-social-180.png / logo-social-400.png
├── logo-app-1024.png
├── brand.json          # 终版：palette/exports/variants/clearspace/min_size/originality_check
├── spec.md             # 几何规范
└── CHECKLIST.md        # 本节走查打勾记录
```

## 7. 反模式

- ❌ 只给一个 PNG 就叫"交付"——那叫"发了张图"
- ❌ 深底版拿浅底版将就——深底陷阱最多，单独做
- ❌ 印刷给 PNG——放大就糊，必须给矢量
- ❌ 对比度"看着还行"——算出来 <4.5 就是不行
- ❌ 命名随意（`logo最终版2真的最终.svg`）——资产管理灾难

## 8. 自检与反馈

交付前自检：

1. `logo_audit.py` blocker 清零？
2. 导出清单 7 类场景全覆盖？（favicon/社交/APP/官网/印刷/深色/单色）
3. `brand.json` 的 `originality_check` 字段填了吗？（填"待做"也算填，诚实比空白强）

标准冒烟：坏 fixture 的尺寸缺失/对比度不足/无深色版埋点必须命中且 exit!=0。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-logo/issues。缺常用尺寸请附场景说明。
